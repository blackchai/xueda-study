# 学习搭子匹配算法 · weighted-v1

第三阶段使用 `backend/app/services/matching.py` 对真实 PostgreSQL 学习档案评分。原有 `frontend/src/utils/matching.ts` 保留为第一阶段演示和单元测试；真实推荐的权威分数来自后端。没有大模型、收费 API、随机数或敏感身份特征。

## 1. 数据来源与隐私

- 当前评分用户来自 Cookie 会话，不接受指定另一个 userId。
- 方向、目标标签、方式、阶段读取 profiles；时间读取 profile_time_slots。
- 只读取用户为匹配主动填写的资料，不从私人 goals/tasks/checkins 自动提取标签或展示学习记录。
- 排除本人；候选必须 matching_enabled=true、账号 is_active=true/status=active，且时区受支持。
- 新老用户的匹配开关均默认 false，须主动开启；查看推荐不要求自己公开。
- 推荐输出只有昵称、公开 UUID、头像首字、方向、标签、方式、阶段、时区、可用时段及解释。学校、专业、简介、邮箱、打卡统计和在线状态不公开。

## 2. 总分

```text
S = round(0.4G + 0.35T + 0.15M + 0.1L)
```

各维度先舍入为 0–100 的整数，再计算总分，最后按 JavaScript Math.round 的正数规则舍入（x.5 向上），不使用 Python 银行家舍入。输出分项可以直接复算总分。资料缺失使用中性分并说明，不改变四个主权重。

## 3. G：学习目标相似度

对两个非空集合计算 Jaccard：`J(A,B)=|交集|/|并集|`。

```text
G = round(100 × (0.65 J(方向) + 0.35 J(目标标签)))
```

预设方向：考研、考公、四六级、编程开发、算法竞赛、专业课程、职业技能、阅读写作。目标标签允许填写 C++、Python、考研数学等，每人最多 20 项、每项 1–32 字。匹配前去首尾空白、转小写、去重；C++ 和 c++ 相同，但 C#、C++ 不等价，不做不透明的语义猜测或别名扩展。

- 任一方某子项为空，该子项不可比较；只在可比较子项内部重新归一化 0.65/0.35 的权重。
- 分类可比较、标签不可比较时，G 只取分类分；反之亦然。
- 两个子项都不可比较时 G=50，并给出资料不完整说明。
- 双方填写且无交集时，该子项是 0 分。

## 4. T：每周学习时间重合度

星期使用 1=周一至 7=周日。时段转为当天分钟数，在每个星期内先合并本人重叠或相邻区间，再计算两人的交集：

```text
O = 每周交集总分钟数
A、B = 双方合并后的每周总可用分钟数
T = round(100 × O / min(A,B))
```

分母用较短一方的时间：若时间较少的人所有空闲均被对方覆盖，则 T=100。自身重复或重叠填写不能增加分数；不同星期即使钟点相同也不重合；恰好在边界相接的两个时段交集为 0。

- 任一方未设时段：T=50、实际 O=0，并明确“时间分按中性值计算”。
- 双方已设但没有重合：T=0，并提示“当前可用时段没有重合”。
- API 校验合法的 HH:mm，开始为 00:00–23:59，结束可至 24:00，且结束严格晚于开始。跨午夜须拆为两天。完全重复时段返回 422；最多 42 个时段。
- 当前统一按 UTC+8：仅支持 Asia/Shanghai 和 Asia/Hong_Kong。其他时区拒绝保存/不进入推荐池，避免把不同时区的钟点错误相交。跨时区、夏令时将在后续独立实现。

## 5. M：学习方式相似度

预设：安静自习、番茄钟、语音陪伴、定期复盘、任务互督、独立学习、相互监督、共同讨论。

```text
M = round(100 × J(方式))
```

任一方缺失时 M=50 并提示；双方已填写无交集则 M=0。不同名字的方式不自动视为同义词。

## 6. L：学习阶段相似度

顺序：入门 → 基础 → 强化（进阶）→ 冲刺。索引距离 0/1/2/3 分别得到 100/70/40/10 分。任一方缺失时 L=50 并提示。

## 7. 可解释结果、排序与筛选

每个候选返回总分、四维分项、真实重合分钟、共同方向/标签/方式/阶段的事实理由，以及缺失偏好或无重合时间的 caveats。不存在共同偏好时说明“暂无已知共同偏好”，不编造学习行为。

接口：GET /api/v1/buddies/recommendations。按公开昵称/方向/标签搜索，按方向、星期、时段或自定义起止时间筛选；overlapOnly=true 只保留真实重合 O>0 的候选。时段筛选判断区间是否相交，不只看开始时间，因此 17:30–19:30 能匹配“晚间”。

先对全部符合条件的候选评分，按 (-score, userId) 稳定排序，再按 page/pageSize 分页。前端只展示当前页，刷新请求重新从数据库读取，不持久化推荐结果到 LocalStorage。

时段通过 ORM selectinload 批量读取，避免每个候选一次查询。候选 N、人均时段 K 时，计算约 O(NK log K)，全局排序 O(N log N)。当前对所有已同意推荐的用户评分，适合早期规模；后续需增加数据库方向预筛、分页游标和候选规模预算，再评估缓存的同意撤回失效策略。

## 8. 三账号可复算样例

均为周一，方式均为“共同讨论”、阶段均为“强化”：

| 账号 | 方向/目标标签 | 可用时间 |
| --- | --- | --- |
| A | 编程开发 / C++ | 19:00–22:00 |
| B | 编程开发 / C++ | 19:30–22:30 |
| C | 考研 / 考研英语 | 08:00–11:00 |

| 比较 | G | T | M | L | S | 每周重合 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| A→B | 100 | 83 | 100 | 100 | 94 | 150 分钟 |
| A→C | 0 | 0 | 100 | 100 | 25 | 0 |
| B 改至 08:00–11:00 后 A→B | 100 | 0 | 100 | 100 | 65 | 0 |

复算：round(40 + 0.35×83 + 15 + 10) = 94。C 得到的 25 分只来自已知相同方式/阶段，不代表目标或时间匹配。所有维度都缺失时为 50 分，并附四类缺失说明；中性分不等于确认合拍。

## 9. 验证与后续演进

- 后端单测：相同资料、标签大小写与 C++、缺失中性值、区间合并、相邻边界、不同星期、阶段距离、舍入规则。
- 接口测试：三真实账号、默认 opt-out、排除本人/禁用用户、修改时段生效、关闭匹配生效、全局排序后分页、筛选、非法输入、档案持久化、未登录及越权拒绝、字段白名单和私人记录隔离。
- 浏览器用三个独立 Cookie 上下文验证真实注册登录、表单保存/刷新、推荐更新和移动布局；不使用个人浏览器资料目录。
- 第四阶段已接入真实邀请/关系状态、接收邀请开关和通知，但这些状态不改变四维评分公式。申请时重查目标的公开/接收开关、有效关系和 pending 请求。匹配权重调整应基于自愿反馈并带算法版本，不用性别、学校层次或私人记录隐式加权。
