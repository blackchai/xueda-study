# 学搭（StudyMate）需求规格说明

> 文档版本：v1.6
> 阶段：第一至第五阶段真实业务 + 第六阶段全站通知与联调验收
> 产品口号：**让自律不再孤单，让学习有人同行。**

> 2026-11-13 更新：认证只支持用户名/邮箱 + 密码。账号、学习业务、档案、匹配、搭子邀请/关系/通知及学习小组均接入真实后端。小组审核、成员、共同目标与打卡授权引用 PostgreSQL 数据；实时聊天暂不开发。

## 1. 产品目标与边界

学搭面向大学生和自主学习者，帮助用户把“想学习”转化为可执行目标，通过每日打卡形成反馈，再借助可解释的搭子匹配与主题小组获得稳定的同伴支持。

第一阶段的高保真前端继续保留。当前账号、会话、目标、任务、打卡、档案和可用时间由 FastAPI + PostgreSQL 持久化；推荐使用主动同意匹配的真实用户。小组使用真实成员和明确授权的个人打卡统计，不复制私人学习数据。

### 1.1 成功标准

- 新用户能在 3 分钟内了解价值、注册登录并创建第一个目标。
- 用户能完成“目标 → 任务 → 打卡 → 查看反馈”的最小学习闭环。
- 用户能理解真实搭子推荐分的来源，调整档案/作息并刷新结果；不会将未开发的邀请显示为已发送。
- 用户能浏览、创建、申请加入和退出真实小组，主动分享个人打卡、查看真实排行榜和共同目标进度。
- 桌面端与手机端均能完成上述核心操作。
- 前端数据访问有独立接口层，第二阶段替换 HTTP 实现时无需重写页面结构。

### 1.2 明确不做

本次不实现：邮箱验证码、密码找回、账号注销、实时聊天、组内独立任务、支付、收费 AI 和大模型推荐。基础搭子通知与邀请关系已在第四阶段落地；真实小组在第五阶段落地。

## 2. 目标用户

| 用户群 | 典型目标 | 主要困难 | 学搭价值 |
| --- | --- | --- | --- |
| 考研/考公/四六级学生 | 长周期备考、阶段冲刺 | 计划庞大、反馈滞后、容易掉队 | 目标拆解、连续打卡、同阶段搭子 |
| 编程/算法学习者 | 项目、刷题、技能进阶 | 学习路径分散、缺少复盘与同行 | 任务管理、标签匹配、共学小组 |
| 习惯养成用户 | 保持固定学习时间 | 开始容易、持续困难 | 可视化积累、温和提醒、连续天数 |
| 寻找学习伙伴的用户 | 互督、结伴自习、共同复盘 | 随机社交效率低、作息不合 | 四维匹配、推荐理由、双向邀请 |

## 3. 用户角色与权限

### 3.1 角色定义

| 角色 | 说明 | 第一阶段 | 第二阶段真实权限 |
| --- | --- | --- | --- |
| 访客 | 未登录访问者 | 浏览首页和登录/注册页 | 不可访问受保护业务页/API |
| 注册用户 | 平台普通用户 | 真实管理自己的目标、任务和打卡 | 其他用户的私有资源不可见/不可改 |
| 小组成员 | 已加入某小组的用户 | 原型已升级为真实业务 | 查看成员内容、主动分享打卡、查看目标进度、退出小组 |
| 小组组长 | 小组创建者或受让者 | 原型已升级为真实业务 | 编辑信息/公告、审核申请、移除成员、设置目标、转让与解散 |
| 平台管理员 | 平台运营和风控角色 | 不在第一阶段前台实现 | 审核举报、冻结账号、处理违规内容、查看审计日志 |

### 3.2 权限原则

1. **最小权限**：普通用户只能修改自己拥有的资源。
2. **资源所有权**：目标、任务、打卡由创建用户拥有；后端必须从身份上下文判断所有者，不能信任前端传入的 `user_id`。
3. **小组作用域**：组内任务、成员名单和排行榜仅向有权限的成员开放；公开小组仅公开摘要。
4. **高风险操作二次确认**：删除目标、退出/解散小组、移除成员均需确认。
5. **前端不是权限边界**：按钮隐藏只改善体验，所有真实权限必须由 FastAPI 再次校验。

## 4. 核心使用场景

### 场景 A：建立学习计划

用户进入目标管理，填写方向、起止日期、标签和目标说明，再添加可在具体日期完成的任务。工作台聚合当天任务，用户勾选后目标进度即时变化。

### 场景 B：完成每日学习打卡

用户在打卡日历选择当天或历史日期，记录学习时长、内容、状态和关联目标。提交后日历点亮，并更新累计时长、月度数据和连续打卡天数。

### 场景 C：寻找学习搭子

用户完善学习方向、目标标签、学习阶段、学习方式和每周可用时间。系统计算候选人的目标相似度、时间重合度、方式一致度和阶段相似度，展示总分、分项分和推荐理由。用户可模拟发送或处理邀请。

### 场景 D：加入主题学习小组

用户按方向搜索公开小组摘要，直接加入或申请等待组长审核，也可创建自己的小组。入组后查看成员私有内容、真实排行榜及目标进度，通过个人打卡入口逐组选择分享；未授权的打卡不公开。

### 场景 E：回顾学习状态

用户在工作台查看今日任务、本周学习节奏、目标进度、连续打卡和推荐搭子，决定下一步行动。

## 5. 功能需求

### FR-01 首页与产品引导

- 展示产品定位、口号、核心学习闭环和搭子匹配特色。
- 提供注册/登录入口。
- 清楚说明第一阶段的数据和账号边界，不虚构真实用户量或效果数据。

### FR-02 账号注册、登录与会话

- 注册需输入用户名、邮箱、密码和确认密码，用户名/邮箱唯一。
- 密码用 Argon2id 哈希，不记录明文；登录失败采用持久化限流。
- 登录支持用户名或邮箱，失败时使用统一提示，不泄露账号是否存在。
- 会话使用 HttpOnly/SameSite Cookie，生产环境强制 Secure；不将密码或令牌写入 LocalStorage。
- 未登录访问业务页会跳转登录页；退出后当前会话立即失效。

### FR-03 学习工作台

- 展示今日任务、完成数、连续打卡天数、本周专注时长和进行中目标数。
- 支持勾选/取消勾选今日任务，并同步更新目标进度。
- 展示近一周每日学习时长柱状图。
- 展示进行中目标进度和最高匹配搭子摘要。
- 提供前往打卡、目标管理和搭子推荐的快捷入口。

### FR-04 目标管理

- 按全部、进行中、已完成、已暂停筛选目标。
- 通过真实 API 创建、编辑和删除当前账号的目标。
- 目标字段包括名称、说明、方向、标签、起止日期、状态和识别颜色。
- 查看基于任务完成数计算的目标进度。
- 为目标添加、编辑、删除任务，设置截止日期和预计时长。
- 支持切换任务完成状态；删除目标前二次确认。

### FR-05 学习打卡

- 展示月历，并明确标记有记录的日期和当前选中日期。
- 点击日期查看当日一条或多条记录。
- 通过真实 API 为当天或历史日期提交打卡；禁止为未来日期打卡。
- 打卡字段包括学习时长、内容、状态和可选关联目标。
- 展示连续天数、本月打卡天数、本月时长、累计时长和最近记录。

### FR-06 学习搭子

- 用户可设置目标分类、标签、阶段、方式、常用时段和可用星期。
- 推荐列表按匹配总分降序排列。
- 支持按公开关键词、目标方向、时段、星期、共同空闲时间筛选及服务端分页。
- 展示总分、分项分、推荐理由、资料缺失/无重合提示和公开匹配档案；不读取私人学习目标或记录。
- 邀请需真实登录，目标同时开启推荐和接收邀请；支持发送/接收、接受/拒绝/取消、我的搭子和解除关系，状态持久化到 PostgreSQL。
- 禁止自邀、重复待处理和重复关系；接受、关系创建和通知同事务。并发操作和批量邀请由数据库锁、唯一约束和账号配额保护。
- 支持四种站内通知、未读计数和已读状态，通过普通 HTTP 查询；仅本人可读，操作其他用户资源返回 404。
- 匹配开关默认关闭，仅主动同意的用户进入推荐池；关闭后下次查询立即移除。

### FR-07 学习小组

- 展示真实小组公开摘要、人数、标签、加入方式和本人状态；内容按成员权限读取。
- 支持搜索、按方向筛选及只看“我加入的”。
- 支持创建/编辑，字段包括名称、方向、简介、标签、人数上限、加入方式和公告；创建者自动成为组长。
- 直接加入或真实待审核、批准/拒绝、本人取消、退出/移除、转让与解散；组长须先转让再退出。
- 复用个人打卡，以分享关联和单独正文授权展示动态；退出、移除、删除原记录均撤回授权。
- PostgreSQL聚合今日/本周/本月时长与累计打卡天数榜，含零记录成员；统一UTC+8、周一开周、去重日期和每组每日24小时上限。
- 组长设置时间区间与每人分钟目标，成员可看自身分享时长进度。个人私有数据不会因加入小组自动公开。
- 组成员复合唯一、pending申请部分唯一、容量/角色/授权由后端和数据库事务保证；前端不伪造加入成功。

### FR-08 个人中心

- 编辑昵称、学校、专业和个人简介。
- 编辑目标分类、标签、阶段和学习方式。
- 添加、编辑、删除每周可用学习时间段。
- 保存每日目标时长、允许被推荐、接收邀请；学校/专业/简介仅本人可见。打卡提醒暂不可用。
- 使用已有真实账号安全会话并可主动退出。
- 真实档案按当前登录身份读写，不接受其他用户 ID；页面刷新保留、跨会话一致。

### FR-09 原型持久化

- 仅显式 Mock 模式的个人业务演示写入 LocalStorage；真实目标、打卡、档案、推荐、邀请和小组不写浏览器持久化。小组不提供虚假多人 Mock 互动。
- 页面刷新后恢复最近操作结果。
- LocalStorage 解析失败或浏览器禁止存储时，回退到内存初始数据且界面仍可用。
- LocalStorage 不是生产持久化方案，不得用于真实密码、令牌或敏感数据。

## 6. 业务规则

1. 目标进度 = 已完成任务数 / 任务总数；没有任务时为 0%。
2. 连续打卡：若今天有记录则从今天向前计算，否则从昨天向前计算；同一天多次打卡只计 1 天。
3. 日学习时长为当日全部打卡时长之和；月度/累计时长同理。
4. 搭子总分使用固定权重公式，所有分项限定在 0～100；详见 `matching-algorithm.md`。
5. 当前原型中“申请加入”会明确提示为模拟通过，不能暗示真实管理员已审核。
6. 小组成员数不得超过上限；已加入时不能重复加入。
7. 目标删除会级联移除其任务；第二阶段打卡中的历史 `goal_id` 应采用 `ON DELETE SET NULL` 保留学习记录。

## 7. 用户操作流程

### 7.1 首次体验主流程

```text
首页了解价值
  → 登录/注册表单或访客体验
  → 进入工作台
  → 创建目标
  → 添加今日任务
  → 勾选任务完成
  → 提交学习打卡
  → 完善匹配偏好
  → 查看推荐理由并发送搭子邀请
  → 浏览或加入学习小组
```

### 7.2 日常学习流程

```text
进入工作台
  → 查看今日任务与预计时长
  → 完成并勾选任务
  → 分段提交打卡
  → 查看本周节奏与目标进度
  → 在搭子/小组中获得同行反馈（第二阶段为真实数据）
```

### 7.3 搭子关系流程（第二阶段真实状态机）

```text
候选推荐 → 发出邀请(PENDING)
  ├─ 对方接受 → ACCEPTED → 创建唯一 buddy_relation
  ├─ 对方拒绝 → REJECTED
  ├─ 发起方撤回 → CANCELLED
  └─ 超时 → EXPIRED
```

## 8. 非功能需求

### 8.1 性能

- 第一阶段生产构建后的首屏静态资源应合理拆包，路由页面采用懒加载。
- 桌面和主流中端手机在正常网络下应快速呈现可操作骨架；第二阶段目标为 LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1（75 分位）。
- 推荐列表第一阶段在本地对几十条数据即时计算；第二阶段后端分页，默认每页 20 条，上限 100 条。
- 列表交互不应因 LocalStorage 写入阻塞明显；大数据量迁移后端后禁止把完整数据集写入浏览器存储。

### 8.2 可用性

- 核心操作有成功、失败、空状态、禁用状态和确认反馈。
- 删除、退出等不可逆/高影响操作必须二次确认。
- 表单错误与具体字段关联，提示中文且可恢复。
- 页面刷新不丢失第一阶段原型操作；存储不可用时仍能继续当前会话。

### 8.3 响应式布局

- 设计基线覆盖 320px 以上手机、平板和桌面。
- 桌面使用侧边导航；手机使用顶部入口与底部主导航。
- 对话框、日历、卡片网格和表单在窄屏下重排，不依赖水平滚动完成核心任务。
- 点击目标尽量不小于 40×40 CSS 像素。

### 8.4 可访问性

- 使用语义化标题、主区域、导航、按钮和表单标签。
- 提供“跳到主要内容”链接；所有关键操作可通过键盘完成。
- 可交互元素有可见焦点；状态不能只依靠颜色表达。
- 正文与背景保持可读对比度，支持 `prefers-reduced-motion`。
- 图表提供文本值或 `aria-label`，弹窗由 Element Plus 管理焦点。
- 第二阶段发布前以 WCAG 2.1 AA 为验收目标并进行自动化与人工检查。

### 8.5 安全与隐私（第二阶段）

- 全站 HTTPS；密码使用 Argon2id 或 bcrypt 哈希，禁止保存明文密码。
- 认证使用 HttpOnly、Secure、SameSite Cookie 或经过评审的等价方案；状态变更请求防 CSRF。
- 输入在后端按 schema 校验，输出编码防 XSS；日志不得记录密码、令牌和私密留言全文。
- 对登录、注册、邀请、建组等接口限流；关键权限操作写审计日志。
- 用户可设置资料可见性；候选推荐只暴露匹配所需的最少资料。
- 前端永远不直接连接 PostgreSQL。

### 8.6 兼容性与可维护性

- 支持当前主流 Chrome、Edge、Firefox、Safari 的最近两个稳定版本。
- TypeScript 严格模式；领域类型统一定义，避免页面自行复制结构。
- Mock 与真实 API 实现同一接口契约；路由页面懒加载。
- 核心算法为无 UI 依赖的独立模块，并有自动化单元测试。

## 9. MVP 范围

### 9.1 第一阶段可演示 MVP

- 8 个完整路由页面和统一响应式视觉体系。
- 本地目标/任务 CRUD、任务完成状态和进度联动。
- 日历打卡、历史记录和时长/连续天数统计。
- 四维搭子匹配、筛选、分项解释、邀请状态原型。
- 小组浏览、创建、加入/退出、成员和排行榜原型。
- 个人档案、匹配偏好、每周时段编辑。
- LocalStorage 原型持久化、Mock API 契约、构建和算法测试。

### 9.2 可上线 MVP（第二阶段最低要求）

- FastAPI + PostgreSQL 实现真实认证、资源所有权与事务。
- 将全部本地 CRUD 替换为真实 API，提供加载、错误、重试和并发冲突处理。
- 真实搭子邀请/关系和小组成员权限，不虚构在线状态。
- 生产环境配置、数据库迁移、日志、监控、备份、限流和安全测试。
- Docker + Nginx 部署、HTTPS、CI/CD 和基础可观测性。
